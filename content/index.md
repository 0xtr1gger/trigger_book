- `Uncategorized` — some useful topics that I don't yet know where to stuff in the current blog structure. As this place expand, I might find it a place.

- `Intelligence` — all about recon, OSINT, enumeration. 
	- `OSINT` — searching public sources.
	- `Asset Discovery` — all about initial reconnaissance stages where you need to get basic information about the target and a list of IP addresses or subdomains to test. 
	- `Web Discovery` — Wab recon which is not exploiting vulnerabilities. 
	- `Nmap` — all about Nmap.

- `Hack the Web` — main place for notes on web application security.

	- `Authentication & Authorization` — vulnerabilities related to authentication, authorization, or session handling, including issues in login flows, JWT attack, OAuth vulnerabilities, and the like.

	- `Injection` — server-side injection vulnerabilities such as SQL injection, S command injection, and so on.

	- `Client-Site` — client-side vulnerabilities such as XSS, CSRF, WebSockets, and others.

	- `Server-Site` — server-side vulnerabilities beyond injection.

	- `Intermediaries` — vulnerabilities that mostly occur due to discrepancies between how the front-end and back-end servers handle user requests, such as `Host` header attacks and HTTP request smuggling.

	- `API` — everything API-specific (REST API, GraphQL).
	
	- `Applications & Friends` — attacking specific applications or frameworks or anything of a kind like CMSs, say, WordPress.
		- `CMS` — well, attacking CMSs.
			- [[WordPress]]

	- `Essential skills` — general techniques that come useful during most attacks, such as encoding obfuscation and quick scanning with Burp Suite.

	- `Cheat Sheets` — a common place for web cheat sheets I made.

	- `Web Knowledge Base` (mostly draft) — a place where I explain how this or that technology works, needed for some attacks and deeper understanding. Includes references with HTTP status codes, headers, etc.


## About note statuses

- There are no "finished" notes on this website. Learning continuously, I know how much I don't know and what my notes might miss. I can't add everything at ones, so I continue developing and gradually bettering this blog. And if I ever happen to thing I wrote everything I needed, I won't make the note "finished" either — it just means I don't yet know what I don't know. 
- But it doesn't mean that all unfinished notes are complete drafts — no. Most of my notes actually look complete and will stay like this for some time for sure. I call those "substantial".
